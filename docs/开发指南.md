# 开发指南

首次开发先完成 [开发环境搭建](开发环境搭建.md)。修改前从 [项目说明](项目说明.md) 确认行为，UI 改动再读 [UI 设计与测试](UI设计与测试.md)；发布流程见 [构建与发布](构建与发布.md)。

## 实现关系

项目保持单 `app` 模块，页面与服务分工如下：

- 手动播放：`MainActivity` / `ui` → `PlayerViewModel` → Media3 `MediaController` → `PlaybackService`。队列、播放状态与计时由服务维护，页面读取状态并发送操作。
- 音乐收录：`PlayerViewModel` → `MusicLibrary` 扫描 MediaStore 或已授权 SAF 目录；播放列表、目录和闹钟通过 `AppStore` 保存。改变 URI 处理时需同时检查扫描、持久化和服务读取。
- 定时播放：`ScheduleScheduler` 计算下次时间并向 AlarmManager 注册指向 `PlaybackService` 的 PendingIntent。服务接收后通过 `consume` 校验触发、推进重复任务并启动播放。重启和时间变化由同文件中的 `ScheduleReceiver` 恢复调度。
- 后台退出：MainActivity → AlarmStandbyService.prepareForExit → 服务前台化并确认任务 → 主动移除卡片。等待服务监听已保存任务变化；PlaybackService 在最后一个单次任务准备播放期间保持等待服务，直到实际出声状态或失败。
- 全屏响铃：PlaybackService → AlarmPresentation 发布全屏通知 → AlarmActivity 显示动画与控制；停止操作校验当前响铃 token，收起只关闭页面。标准全屏通知授权之外，vivo 还需允许“锁屏显示”；独立诊断对话框尚未恢复。
- 倒计时复用 Schedule 和现有调度链路，countdownAt 保存绝对截止时间；新增 CountdownTest 与 AlarmTokenTest 验证时间和实例校验。首次使用手册、更多菜单帮助及设置中的使用说明共用同一对话框。

逐个文件的职责见 [项目说明的实现位置](项目说明.md#实现位置)。闹钟规则、旧数据兼容和目录授权行为以项目说明为准。

## 测试与设备运行

使用匹配的 JDK，在项目根目录按改动需要执行：

```sh
./gradlew :app:testDebugUnitTest
./gradlew :app:lintDebug
./gradlew :app:connectedDebugAndroidTest
```

最后一项需要已启动且授权的设备或模拟器。存在多台设备时，先确认测试对象；不要把 API 37 模拟器的结果记成 API 35 真机结果。

[PlaybackIntegrationTest](../app/src/androidTest/java/com/Huffer342/shiyin/PlaybackIntegrationTest.kt) 用静音 WAV 验证扫描、追加队列不中断、手动媒体模式、睡眠定时设置/取消/一分钟到期停止、5 秒淡入及 30 秒试听上限、Activity 停止后的闹钟触发、无 Activity/控制器连接的服务冷启动，以及文件不可访问时的失败记录和清理。运行约 3–5 分钟。测试需要 API 29 及以上，须先在系统设置授予时音“闹钟和提醒”。它会授予本应用音频/通知权限，并清理自己创建的歌曲和任务，建议使用专用模拟器。

保留应用安装状态的复跑方式：

```sh
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest
adb -s SERIAL install -r app/build/outputs/apk/debug/app-debug.apk
adb -s SERIAL install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s SERIAL shell am instrument -w -r com.Huffer342.shiyin.test/androidx.test.runner.AndroidJUnitRunner
```

成功条件为 `OK (N tests)` 且没有失败；测试数量以本次 runner 输出和实际运行范围为准；历史运行结果见 [验证记录](验证记录.md)。仅有 adb 退出码 0 不代表断言通过。新增的导航与编辑交互测试、测试音频导入方式见 [UI 设计与测试](UI设计与测试.md)。

[ScheduleTest](../app/src/test/java/com/Huffer342/shiyin/ScheduleTest.kt) 覆盖星期重复、过期单次任务、禁用任务、调休补班、跨年缺失日历、旧/重复/迟到触发、时区变化以及 JSON 往返与非法数据。模板加法和包名测试仍保留，不代表业务验证。构建与单元测试不能证明后台音频或耳机路由可靠。

手动安装和启动应用：

```sh
adb devices -l
# 将 SERIAL 替换为上一步选定设备的序列号。
adb -s SERIAL install -r app/build/outputs/apk/debug/app-debug.apk
adb -s SERIAL shell am start -n com.Huffer342.shiyin/.MainActivity
```

成功条件：安装返回 `Success`，应用打开并显示预期页面，无启动崩溃。记录实际设备和系统版本。安装前确认是自己的开发包；不要为解决签名或安装冲突直接卸载已有应用，以免丢失数据。

## Android 15 真机验收

使用自有测试音频，先确认音量，分别检查以下场景：

- 拒绝/允许本地音频权限、永久拒绝后进入设置、撤销权限后再次扫描或触发任务。
- 扫描、搜索、队列、进度拖动、循环/随机、通知栏与锁屏播放控制。
- 手动播放使用媒体音量；试听和定时使用闹钟音量。试听 30 秒结束，定时按设定分钟数停止。
- 有线、USB 和蓝牙耳机连接时实际输出；耳机断开是否暂停；来电或其他音频占用后的行为。
- 一次、星期重复、中国大陆工作日规则；补班周末、放假工作日、跨年缺数据与更新失败。
- 创建、编辑、禁用、删除多个任务；重启、改时区、撤销/重新授予精确闹钟权限后的恢复。
- 返回桌面、划掉最近任务、锁屏、Doze 和系统回收进程后是否按时播放。强行停止单独记录，不能算成普通进程回收。
- 文件被删除或解码失败时，应用内消息和获准后的异常通知是否可见。

模拟器用于快速检查，vivo Android 15 真机用于确认后台、电池限制和耳机输出。不得把 API 37 模拟器结果记成 API 35 真机结果。重启后首次解锁前的播放、关机播放及强行停止后的自动恢复不在当前支持范围。

## 后台闹钟排查

启动保护与诊断记录的含义见 [项目说明](项目说明.md#闹钟启动与诊断)。

复测时先在设置确认闹钟、通知和音频权限。保存近期闹钟后在底部 tab 栏上滑进入后台，检查 AlarmStandbyService 的 isForeground、包 stopped 状态、最近任务与 AlarmManager 预约，再锁屏观察。错误信息通过应用内消息与播放异常通知查看。无卡片、服务运行、闹钟送达、焦点获准、实际出声和按时停止分别记录；手动上划必须单独测试。历史实验数据和下一步见工作记录。
