# 项目说明

时音是 Kotlin + Jetpack Compose 的本地音乐与定时播放器。

## 播放器

主栏目为歌曲、播放列表、目录、闹钟，可左右滑动切换。手动播放支持队列、进度、随机/循环、迷你播放器、通知控制和睡眠定时。手动播放使用媒体音量，闹钟与试听使用闹钟音频属性。

音乐来自 MediaStore 或用户授权的本地 SAF 目录。目录支持逐层浏览、递归音频集合、多选及加入播放列表；前台使用时检测变化，重新打开补扫，不为目录扫描单独常驻后台。支持的实际文件仍受系统解码器和授权状态影响。

播放列表、监控目录、闹钟、主题和工作日日历继续使用原有 shiyin SharedPreferences，不清除用户数据。备份规则排除设备相关任务数据，避免跨设备恢复无效媒体引用。

## 闹钟

支持一次、每周重复和中国大陆法定工作日规则；工作日日历需按年份更新。任务可设置淡入、单次播放上限，试听最多 30 秒。单次上限包含准备、暂停与等待时间。

ScheduleScheduler 通过 AlarmManager.setAlarmClock 注册任务，触发时校验任务标识、预期时间和有效窗口。重复任务计算下一次时间；一次任务触发后禁用。错过有效窗口不补播。重启、系统时间/时区及授权变化后按现有规则重建未来任务。

倒计时按保存的截止时刻触发，修改系统时间会改变剩余等待时间。点击倒计时卡片或重新启用任务，会从原设定时长重新计时。旧任务缺少总时长时，应用会提示重新设置。

音频失效、日历缺失、权限拒绝或音频焦点申请失败时，可在应用内查看错误信息。

## 后台运行与主动关闭卡片

在底部 tab 栏向上滑动，或从歌曲首页按返回，进入统一退出流程：

1. 有启用的闹钟时，确认精确闹钟和通知权限，以及任务已注册。
2. 可见页面启动闹钟前台等待服务，等待服务回复就绪。
3. App 调用 finishAndRemoveTask 关闭自己的任务卡片；MainActivity 使用 singleTask，避免重复启动产生同类页面栈。
4. 等待通知显示下一次播放时间，点击可回到 App。权限不足、启动异常或超时会保留页面并提示。

没有启用的闹钟时，直接关闭卡片，不额外启动等待服务；已有手动音频仍由播放服务管理。等待期间不播放无声音频、不持有唤醒锁、不忙循环。Android 14+ 的等待服务使用 systemExempted 类型，资格来自已获准的精确闹钟权限。

全部任务取消、禁用或不再有有效预约后，等待服务退出。最后一个单次闹钟被消费时，等待服务保持到播放器实际开始或准备失败，以免在申请焦点前丢失前台状态。重复任务还有下次预约时继续等待。

## 闹钟启动与诊断

播放服务在校验和准备音频前发布前台通知，并注册 MediaSession，使其不依赖页面控制器存活。准备阶段持有有时限的唤醒锁；超过 15 秒未进入实际播放会停止并报告失败。播放开始、停止、取消及销毁都会清理准备状态。

响铃通知可打开全屏动画，显示剩余时间。收起页面后继续播放，停止按钮只结束本次响铃。系统未授权全屏显示时，可点击通知进入响铃页。vivo 设备的锁屏权限见[使用手册](使用手册.md#全屏响铃)。

## 已知限制与验证状态

- 在 vivo 实验中，用户手动上划卡片会导致整个包停用、预约消失；主动关闭自身卡片与系统上划清理是不同操作。前台服务并非厂商白名单。
- SDK 34 实验包与 targetSdk 37 正式播放器已分别有无卡片锁屏出声的短时样本；正式包 2026-11-17 17:30 样本获用户听感确认，播放服务随后退出。尚未通过三次重复和长期验收。
- 等待服务使用 START_STICKY 请求系统回收后重建；使用过后台运行且有未来任务时，开机解锁或覆盖升级后尝试恢复等待服务。恢复条件已有单元测试，真实进程回收、开机与厂商自启动效果仍待验证。强行停止后不能保证自动恢复。
- 单 App 普通权限是当前约束；不采用独立守护 App、外部特权守护或依赖 ADB 常驻。

操作与验证见[开发指南](开发指南.md)，界面约定见[UI 设计与测试](UI设计与测试.md)，后续安排见[工作记录](工作记录/README.md)。
