# 项目说明

时音是 Kotlin + Jetpack Compose 的本地音乐与定时播放器。

## 播放器

主栏目为歌曲、播放列表、目录、闹钟，可左右滑动切换。手动播放支持队列、进度、随机/循环、迷你播放器、通知控制和睡眠定时。手动播放使用媒体音量，闹钟与试听使用闹钟音频属性。

歌曲行菜单的“详细信息”显示来源、文件名、位置、格式、大小、时长和比特率。信息由现有媒体 URI 读取；提供者未返回的字段显示为“未知”，不影响播放。用户点击位置可复制路径，长按并确认后可通过系统文件管理器打开所在目录。

音乐来自系统音乐库（MediaStore）和用户授权的本地 SAF 目录，两种来源可同时启用。系统音乐库默认开启，默认排除 `Recordings/` 及其子目录；用户可在“目录 → 系统音乐库”中关闭整个来源，或按 MediaStore 实际目录调整收录开关。自选目录始终按用户授权递归扫描，即使同一路径已从系统音乐库排除。合并来源时按存储位置去重，自选目录优先。目录支持逐层浏览、递归音频集合、多选及加入播放列表；前台使用时检测变化，重新打开补扫，不为目录扫描单独常驻后台。支持的实际文件仍受系统解码器和授权状态影响。

播放列表、监控目录、闹钟、主题和工作日日历继续使用原有 shiyin SharedPreferences，不清除用户数据。备份规则排除设备相关任务数据，避免跨设备恢复无效媒体引用。

## 闹钟

支持一次、每周重复和中国大陆法定工作日规则；工作日日历需按年份更新。任务可设置淡入、单次播放上限，试听最多 30 秒。单次上限包含准备、暂停与等待时间。

ScheduleScheduler 通过 AlarmManager.setAlarmClock 注册任务，触发时校验任务标识、预期时间和有效窗口。重复任务计算下一次时间；一次任务触发后禁用。错过有效窗口不补播。重启、系统时间/时区及授权变化后按现有规则重建未来任务。

倒计时按保存的截止时刻触发，修改系统时间会改变剩余等待时间。点击倒计时卡片或重新启用任务，会从原设定时长重新计时。旧任务缺少总时长时，应用会提示重新设置。

音频失效、日历缺失、权限拒绝或音频焦点申请失败时，可在应用内查看错误信息。

## 后台运行与主动关闭卡片

在底部 tab 栏向上滑动，或从歌曲首页按返回，进入统一退出流程：

1. 有启用的闹钟时，确认精确闹钟和通知权限，以及任务已注册。
2. 可见页面启动闹钟前台等待服务，等待服务回复就绪。
3. App 调用 finishAndRemoveTask 关闭自己的任务卡片；MainActivity 使用 singleTask，避免重复启动产生同类页面栈。
4. 等待通知显示下一次播放时间，点击可回到 App。权限不足、启动异常或超时会保留页面并提示。

没有启用的闹钟时，直接关闭卡片，不额外启动等待服务；已有手动音频仍由播放服务管理。等待期间不播放无声音频、不持有唤醒锁、不忙循环。Android 14+ 的等待服务使用 systemExempted 类型，资格来自已获准的精确闹钟权限。

全部任务取消、禁用或不再有有效预约后，等待服务退出。最后一个单次闹钟被消费时，等待服务保持到播放器实际开始或准备失败，以免在申请焦点前丢失前台状态。重复任务还有下次预约时继续等待。

## 闹钟启动与诊断

播放服务在校验和准备音频前发布前台通知，并注册 MediaSession，使其不依赖页面控制器存活。进入定时播放时先发布全屏响铃通知并启动响铃页，再申请 `USAGE_ALARM` 音频焦点；若首次被系统后台限制拒绝，会在 3 秒内异步重试焦点（最多 15 次 × 200ms）并直接以闹钟属性开始播放，不因焦点延迟而中止响铃。准备阶段持有有时限的唤醒锁；超过 15 秒未进入实际播放会停止并报告失败。播放开始、停止、取消及销毁都会清理准备状态。

响铃通知可打开全屏动画，显示剩余时间。收起页面后继续播放，停止按钮只结束本次响铃。系统未授权全屏显示时，可点击通知进入响铃页。vivo 设备的锁屏权限见[使用手册](使用手册.md#全屏响铃)。

## 可选闹钟守护包

- 在 vivo 等国产系统上，即使用户在系统最近任务手动上划卡片或点击「清除全部（×）」，单应用也会被系统 `forceStopPackage` 强行停止并清空 `AlarmManager` 预约。为应对该系统限制，项目提供**可选**同签名配套模块 `:guard`（应用名「时音闹钟守护」，包名 `com.Huffer342.shiyin.guard`）。
- **独立可用与可选安装**：不安装 `:guard` 时，`ShiYin` 仍以单应用普通权限模式完整运行；首次切换到闹钟栏目时通过 `GuardSetupDialog` 提示一次（可跳过），也可随时在「设置 → 闹钟守护包」或「权限与后台」中安装、配置或卸载。Debug 和发布流程生成的 Release 均内置与主包同签名的守护 APK，通过 `FileProvider` 拉起系统安装器。
- **无图标与跨包通信**：`:guard` 不注册桌面 `LAUNCHER` 入口，`GuardActivity` 设置 `excludeFromRecents="true"` 并在完成引导时调用 `finishAndRemoveTask()` 不留最近任务卡片。主应用在保存、删除、重算和消费闹钟时，通过受 `signature` 权限 `com.Huffer342.shiyin.permission.COMPANION_ALARM` 保护的 `GuardSyncProvider` 将未来预约同步给 `GuardAlarmStore` 并由其调用 `AlarmManager.setAlarmClock`。
- **唤醒与卸载清理**：到点后 `GuardFireReceiver` 发送带 `FLAG_INCLUDE_STOPPED_PACKAGES` 的广播至 `CompanionAlarmReceiver` 拉起 `PlaybackService`（广播失败时回退直接拉起前台服务）。主应用被卸载时，`GuardReceiver` 收到包移除广播后会清空全部守护预约，并在获授通知权限时弹出提醒通知以便用户一键卸载守护组件。

## 已知限制与验证状态

- 未安装守护包时，在 vivo 实验中手动上划单应用卡片会导致整个包停用、预约消失；主动关闭自身卡片与系统上划清理是不同操作。前台服务并非厂商白名单。
- 安装 `:guard` 并授予守护“精确闹钟”以及 vivo 系统的「允许后台高耗电」「自启动」「关联启动」后，已在 vivo OriginOS 5（Android 15）真机上实测通过**最近任务未加锁居中单卡上划**与**最近任务未加锁「清除全部 (×)」**后的 0 秒延迟冷唤醒响铃；后续针对拔线复测出现的后台音频焦点拒绝已调整 `PlaybackService` 启动与重试顺序，该次修复待重连真机验证。
- 单应用模式下，等待服务使用 START_STICKY 请求系统回收后重建；使用过后台运行且有未来任务时，开机解锁或覆盖升级后尝试恢复等待服务。恢复条件已有单元测试，真实进程回收、开机与长时间 Doze 效果仍待验证。未安装守护包且强行停止后不能保证自动恢复。
- 主应用保持普通权限，不依赖无障碍模式、Shizuku 或桌面小组件；配套守护组件由用户按需显式安装。

操作与验证见[开发指南](开发指南.md)，界面约定见[UI 设计与测试](UI设计与测试.md)，后续安排见[工作记录](工作记录/README.md)。
