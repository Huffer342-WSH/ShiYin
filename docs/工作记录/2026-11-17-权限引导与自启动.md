# 权限引导与自启动

## 实现

- 首次打开自动展示权限与后台设置，用户点击后申请音乐/通知，拒绝可继续使用；精确闹钟和全屏通过系统专用设置授权。没有自动切换厂商开关。
- 全局固定顶部提供“权限与后台”和“后台运行”，覆盖主栏目、目录/播放列表详情、设置、主题、播放页和闹钟编辑页。弹出的模态对话框需先关闭；编辑未保存时进入后台会二次确认。
- 引导提醒锁定最近任务卡片、允许厂商自启动和后台运行；主动后台运行仍会移除卡片。
- 等待服务改为 START_STICKY，支持普通系统回收后重建，启动时重新校验权限与任务，无任务则停止。
- 原有 BOOT_COMPLETED/MY_PACKAGE_REPLACED 恢复预约后，仅在用户已使用后台运行且仍有未来任务时恢复等待服务。失败记录到应用提示，不从开机广播直接启动媒体播放服务。

## 边界

开机恢复发生在解锁后；未实现 Direct Boot。系统强行停止、OriginOS 停用包和厂商省电仍可能阻止广播或重建。自启动开关不代表误划后必定恢复，不以 sticky 替代长锁屏与实际重启验证。

参考：[Android Service 重建语义](https://developer.android.com/reference/android/app/Service)、[前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)。

## 验证

已补充恢复条件单元测试：用户未启用、无任务、禁用、过期均不恢复；未来任务恢复。导航测试适配首次引导并检查全局按钮。assembleDebug、testDebugUnitTest、lintDebug、assembleDebugAndroidTest 均通过。首次安装因设备未连接中止；用户重新连接后，20:06 在 vivo V2463A 覆盖安装成功，保留数据。观察到首次权限引导正常显示、既有权限正确标为已允许；关闭后切到闹钟栏目，顶部两按钮仍可见，并成功重新打开权限引导。本轮仅做人工 UI 抽查，未执行 instrumentation，未验证全新安装时权限拒绝、普通进程回收或真实开机。未重启用户手机。
